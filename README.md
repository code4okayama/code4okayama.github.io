# Code for Okayama Webサイトの管理

このリポジトリは、Code for OkayamaのWebサイトを管理するためのものです。公開するファイルは `docs/` に置き、GitHub Pagesで配信します。このREADMEは、担当者が内容を更新・確認・公開するための手順をまとめています。

## ファイル構成

HTML・CSS・JavaScriptだけで構成する静的サイトです。ビルドやパッケージのインストールは不要です。

```text
README.md                # 管理・更新の手順
.gitignore               # macOSのメタデータを除外
docs/
├── .nojekyll             # Jekyllの処理を無効化
├── index.html            # ページ本文・リンク・検索／共有用の情報
├── css/style.css         # 配色・レイアウト・スマートフォン対応
├── js/main.js            # モバイル用ナビゲーションの開閉
└── img/
    ├── general/          # サイト共通のロゴ・イラスト・アイコン
    ├── member/           # 個人メンバーのプロフィール画像
    └── member-org/       # 組織メンバーのロゴ
```

個人・組織ごとの画像ファイル名やプロフィールはこのREADMEには列挙せず、`docs/index.html` で管理します。

## 通常の更新手順

1. 下の「内容の更新」を参考に、HTML・CSS・画像を変更します。
2. ローカルでページを開き、PCとスマートフォン幅で表示・操作を確認します。
3. `git status --short` と `git diff` で、今回の変更内容を確認します。画像を追加・移動した場合は、対象の画像もコミットに含めます。
4. 変更をコミットし、GitHub Pagesの公開元ブランチにプッシュします。
5. GitHubの **Actions** でデプロイ完了を確認し、公開サイトで変更箇所を確認します。

公開元ブランチや公開URLは、リポジトリの **Settings → Pages** で確認してください。

## 内容の更新

本文とリンクは、原則として `docs/index.html` を編集します。

| 更新する内容 | 編集する場所 |
| --- | --- |
| 最初のティザー | `id="top"` |
| イベント告知 | `class="event-band"` |
| 団体紹介 | `id="about"` |
| 大切にすること | `id="approach"` |
| 活動の進め方・活動例 | `id="activities"` |
| 個人・組織メンバー | `id="members"` |
| 参加案内・問い合わせ先 | `id="join"` |
| よくある質問 | `class="faq"` |
| ナビゲーション | `id="site-nav"` |

セクションのIDはページ内リンクに使います。変更・追加する場合は、ナビゲーションや本文の `href="#..."`、見出しを参照する `aria-labelledby`、セクション番号も合わせて更新します。

### イベント

イベントへの導線は次の3か所にあります。新しいイベントに切り替えるときは、URLと案内文をまとめて更新します。

- ティザーと団体紹介の間の告知：`class="event-band"`
- 参加案内のリンク：`class="event-link"` と、その下の `class="event-note"`
- FAQの「活動日程や参加方法はどこでわかりますか？」

告知にはイベント名、日時、会場、概要を掲載します。日付を変更するときは、表示上の日時・曜日だけでなく `<time datetime="...">` も更新してください。日本時間の場合、`datetime` のタイムゾーンは `+09:00` です。

イベント終了後は、告知を「開催済み」にするか、`event-band` の `aside` 要素全体を削除します。参加案内とFAQも、次のイベントや一覧ページなど、その時点で適切な案内に切り替えてください。詳細な開催条件や申込方法は、リンク先のイベントページと一致させます。

### 個人メンバー

`class="member-grid"` 内の `article` 要素を追加・編集します。名前、所属・役職、画像、Webサイトへのリンクを設定してください。

画像は `docs/img/member/` に置きます。「準備中」の枠を使う場合は、`member-pending` クラスを外し、`member-placeholder` の要素を画像に差し替えてから紹介文を更新します。

### 組織メンバー

`class="org-member-grid"` 内の `figure` 要素を追加・編集します。

- `figcaption`：組織名
- `class="org-logo-panel"` の `a` 要素：組織のWebサイトURLと `aria-label`
- その中の `img` 要素：ロゴ画像と `alt`

ロゴは `docs/img/member-org/` に置きます。組織名はロゴの上に表示し、ロゴ画像からWebサイトへリンクする構成です。

### 問い合わせ先・ページ情報

問い合わせ先を変える場合は、参加案内とFAQにあるメールアドレスの表示、`mailto:` のリンク先を両方更新します。

検索結果や共有時の情報は、HTMLの `head` 内の `title`、`meta description`、`og:title`、`og:description` で管理します。公開URLや共有画像を設定する場合は、canonical、`og:url`、`og:image` を追加・更新してください。

### 画像・デザイン

画像は用途に応じて `img/general/`、`img/member/`、`img/member-org/` に配置します。`docs/img/` 直下には置きません。

HTMLからの参照には `./img/general/...` のような相対パスを使います。画像の移動・名前変更時は、ヘッダー・フッターを含む参照先をすべて更新してください。`img` の `alt` は画像の内容に合わせ、`width`・`height` には元画像の寸法を設定します。

配色とレイアウトは `docs/css/style.css` で管理します。基本色は `:root` の緑 `--green: #093e32` と橙 `--orange: #fa8c72` です。余白や画像サイズを変える場合は、末尾のメディアクエリによるスマートフォン向け指定も確認してください。

## ローカルでの確認

リポジトリのルートで、次のコマンドを実行します。

```sh
python3 -m http.server 8000 --directory docs --bind 127.0.0.1
```

ブラウザで <http://127.0.0.1:8000/> を開きます。終了するにはターミナルで `Ctrl+C` を押します。簡単な確認なら `docs/index.html` を直接ブラウザで開くこともできます。

更新した箇所に応じて、次を確認してください。

- PC・スマートフォン幅で、文字や画像に欠け・重なり・横へのはみ出しがないこと
- モバイルメニュー、ページ内リンク、FAQの開閉が動くこと
- イベント・メンバー・組織ロゴのリンク先と、メールリンクが正しいこと
- 画像が表示され、移動前のパスへの参照が残っていないこと
- 日時・会場・所属などの記載が、掲載元の情報と一致すること

JavaScriptを無効にしても本文・ナビゲーション・FAQを利用できる構成です。ナビゲーションを変更する場合は、この状態でも確認してください。

## GitHub Pagesの公開設定

初回設定、または公開元を変更する場合の手順です。

1. 公開するファイルをGitHubの対象ブランチにコミット・プッシュします。
2. リポジトリの **Settings → Pages** を開きます。
3. **Build and deployment → Source** で **Deploy from a branch** を選びます。
4. 公開元のブランチとフォルダ **/docs** を指定し、**Save** を押します。
5. デプロイ完了後、Pages設定に表示された公開URLで確認します。

設定後は、公開元ブランチへのプッシュで更新します。`docs/.nojekyll` は公開用ファイルとして管理し、削除・除外しないでください。

公式手順：[GitHub Pagesの公開元の設定](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 更新が反映されない場合

GitHubの **Actions** でデプロイの完了・エラーを確認し、**Settings → Pages** の公開元が変更をプッシュしたブランチと `/docs` になっているか確認します。

デプロイ済みでも表示が古い場合は、ブラウザを強制再読み込みします。Macでは `⌘ + Shift + R` です。画像だけ表示されない場合は、HTMLの参照先、ファイル名の大文字・小文字、画像がコミットされているかを確認してください。
